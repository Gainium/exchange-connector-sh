# 001 — Wire real mocha to the scattered hand-rolled unit specs

## Build order

1. Add devDependencies: `mocha`, `@types/mocha`.
2. Convert the 7 fully-synchronous files (`redact`, `serializeParams`,
   `orderFee`, `keyPermissions`, `fill-price`, `cancel-verdict`,
   `partial-fill`) with the minimal-diff pattern: redefine the file's own
   `expect`/`check` helper to call `it(label, () => { <original
   comparison>; if (!ok) throw ... })`, wrap the body in one top-level
   `describe(...)`, leave every individual assertion call site untouched.
3. Convert the 10 async files with the `before()`-hook pattern (§3.2):
   hoist the original function body's computation into `before(async ()
   => {...})`, storing results in `let`-declared outer variables; replace
   `expect(label, value, want)` call sites with `expect(label, () =>
   value, want)` so the getter is evaluated lazily inside `it()`, after
   `before()` has populated the variables. `venue-fee-capture.spec.ts`
   instead gets one `it(label, async () => {...})` per assertion, no
   shared `before()`, since its setup is cheap per-case.
4. Add an npm `"test"` script: mocha over `src/**/*.spec.ts` via
   `ts-node/register`, with `TS_NODE_TRANSPILE_ONLY=1` (§3.3).
5. Run `npm test` and diff the pass count against the baseline (§4):
   329 in, 329 out, exactly — no silent drift from the async-registration
   restructuring or from any comparator change (there is none; every
   file's original `===`/`JSON.stringify` comparator was preserved
   verbatim).
6. Add `.github/workflows/test.yml`: PR + push to `main`, Node 22,
   `npm ci`, `npm test`.

## Contract decisions (§3.1, §3.2)

mocha (no chai) added as a devDependency, pre-authorized by this task's
brief. The async files use `before()`-hook precomputation rather than
per-`it()` async recomputation, except `venue-fee-capture.spec.ts` where
per-case setup is cheap enough that async `it()` callbacks are simpler
and there's no shared state worth hoisting.

## Blast radius

1. **Other call sites.** None of the 17 files are imported by anything
   else — leaf test files, not modules other code depends on. Verified
   for the specific case in `hyperliquid/bad-address.spec.ts` §1.3 (the
   `instrumentFetch` global-fetch patch is restored before the file's
   `before()`/`it()`s complete, scoped to this file's own process).
2. **`core/` submodule.** This repo (`exchange-connector-sh`) has no
   `.gitmodules` — it *is* what `exchange-connector` submodules as
   `core/`. That repo's own CI (checking out this content at a pinned
   commit) is a separate, later change — out of scope here.
3. **CLAUDE.md-documented contracts.** No exchange-connector API/queue
   shape changes — test-file, devDependency, and CI-file changes only.
   The modules under test are not touched.
4. **Other tests exercising this path.** None — these are the only
   tests for these modules today.
