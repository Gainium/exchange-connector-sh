# 009 — plan

Spec: [`specs/009.bybit-linear-positions-settle-coin-loop-unhandled-rejection.md`](../specs/009.bybit-linear-positions-settle-coin-loop-unhandled-rejection.md)

## Solution

One file, one loop body:
`core/src/exchange/exchanges/bybit/index.ts` → `futures_getPositions`, the
`category === 'linear' && !symbol` branch.

Give the loop body the two arms the per-symbol branch already has, reusing the
class's existing `handleBybitErrors` / `BybitError` — no new helper:

1. `.then()` gains an `else`: a non-`OK` `retMsg` becomes
   `handleBybitErrors(...)(new BybitError(result.retMsg, result.retCode))`.
2. `.catch(handleBybitErrors(...))` is added for the rejection case.
3. The handled `BaseReturn` is **returned from `futures_getPositions`**, aborting
   the loop — spec §1.1: no partial list.

Both handlers get `(this.futures_getPositions, symbol, endProfilerTime(...))`.
`symbol` is `undefined` here, and passing it explicitly is what keeps
`handleBybitErrors`' retry (`cb.bind(this)(...args)`) on the settle-coin branch
(spec §3). The per-symbol branch's own omission of `symbol` is spec §4,
out of scope.

No new utility: `handleBybitErrors` (L1902) is the repo's existing error
contract for this venue and already covers retry/backoff/`returnBad`.

## JIT legacy tier

**Tier 0** — nothing is extracted. The decision logic on the causal path *is*
`handleBybitErrors`, which is already a single named method the whole class
shares; the fix is to call it where it was skipped. Extracting the loop into a
pure module would not remove a smell (the loop is pure I/O sequencing) and would
be a drive-by rewrite of a 1900-line venue class.

## Blast radius

1. **Other call sites.** `futures_getPositions` is the only caller of this loop;
   the loop body is not shared. Callers of `futures_getPositions` already handle
   `BaseReturn` NOTOK — main-app `src/positionReconciler/venue.ts` has the
   `else { snap.errors.push('positions: ' + res.reason) }` arm, which is today
   unreachable for this failure because the call rejects instead. exchange-
   balancer forwards the `BaseReturn` untouched.
2. **`core/` submodule.** Yes — this file is in `exchange-connector-sh`, shared
   and deployed platform-wide. The change is confined to one Bybit method and
   adds no new exported symbol, so the ripple to paper-trading (contract mirror)
   is nil: the response *shape* is unchanged, only which shape is produced for a
   failure that today produces none.
3. **Owned contracts** (`CLAUDE.md` "What this service OWNS / EMITS"):
   `BaseReturn<T>` is untouched — this makes a path that *violated* it comply.
   `/positions` keeps its signature. No Redis channel, no endpoint change.
   Behaviour change for consumers: an HTTP 500 becomes an HTTP 200 with
   `{status: NOTOK, reason}`, and a silently-short OK list becomes NOTOK. Both
   are the contract being honoured, and NOTOK is a shape every consumer of this
   endpoint already handles.
4. **Other tests on this path.** No existing spec touches
   `futures_getPositions`; the whole `core` mocha suite must stay green, plus
   `tsc --noEmit` in **both** `core/` and the parent (the parent has a coupled
   stale copy of `src/`).
