# 011 — plan

Spec: [`specs/011.retry-log-lines-print-plaintext-api-key.md`](../specs/011.retry-log-lines-print-plaintext-api-key.md)

## Solution

1. New `core/src/utils/keyFingerprint.ts` exporting `keyFingerprint(key)`: djb2
   over the key, rendered base36, identical to `hashKrakenKey` (spec §1.1 "same
   fingerprint on every venue").
2. In each line of spec §1.2, replace `${this.key}` with
   `key#${keyFingerprint(this.key)}`. The `key#` prefix marks the token as a
   fingerprint, so nobody mistakes it for a key or searches a venue for it.
   Nothing else in the lines changes.

Kraken is not moved onto the helper (spec §4). Its `hashKrakenKey` also keys
module-level caches, and a separate change is working in that file; leaving it
alone keeps this change free of cache-key risk. The spec's last test pins the
helper to the same scheme, so the two cannot quietly diverge.

## JIT legacy tier

**Tier 2 for the new helper, Tier 0 for the handlers.** The helper is a pure
function with no imports. The handlers are large legacy retry ladders, but the
defect is a single interpolated token per line. Extracting the ladders would
not remove the smell this spec is about, and would be a drive-by rewrite.

## Blast radius

1. **Other call sites.** A grep for `${this.key}`, `${this.secret}` and
   `${this.passphrase}` across `core/src` leaves only the Hyperliquid lines,
   which are out of scope (spec §4). No log line interpolates a secret.
2. **`core/` submodule.** Yes. Shared and deployed wherever the connector
   runs, including self-hosted. The change adds one exported utility and alters
   log text only.
3. **Owned contracts** (`CLAUDE.md` "What this service OWNS / EMITS"):
   untouched. No `BaseReturn`, endpoint, Redis channel or config change.
   **Log text is not a contract**: no service or monitoring script parses these
   lines (searched the platform services and the ops tooling). Anyone who
   greps logs for a raw key to find an account now greps for its fingerprint.
4. **Other tests on this path.** No existing spec drives these three handlers'
   rate-limit branches. The whole `core` mocha suite must stay green, plus
   `tsc --noEmit` in `core/` and in the parent, which wraps these adapters.
