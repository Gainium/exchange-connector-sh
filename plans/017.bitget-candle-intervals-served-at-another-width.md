# 017 — plan: serve every Bitget interval at the width it names

Spec: [`../specs/017.bitget-candle-intervals-served-at-another-width.md`](../specs/017.bitget-candle-intervals-served-at-another-width.md)

## 1. Solution

Two moves, both inside the Bitget adapter. Neither introduces a new helper —
the merge already exists (`uta.ts:241 aggregateCandles`) and so does the
recurse-at-the-base-interval shape (`index.ts:3117`, the Reality branch).

### 1.1 — ask for the granularity the venue actually has

`convertInterval` substitutes three widths. Two of the substitutions are
unnecessary (spec 017 §2.1):

| interval | today | becomes |
|---|---|---|
| `3m` futures | `1m` | `3m` |
| `3m` spot | `1min` | `3min` |
| `2h` futures | `1H` | `2H` |
| `2h` spot | `1h` | unchanged — spot has no 2h, §1.3 covers it |
| `8h` both | `6Hutc` | unchanged — no line has 8h, §1.3 covers it |

`3min` is missing from the SDK's `SpotKlineInterval` union (it stopped at the
v1 docs) though the live endpoint serves it and names it in its own error text.
Widen the adapter's own return type once, with the measurement in a comment,
rather than casting at the call site — a cast at the call site is what let the
original substitution go unnoticed.

### 1.2 — merge the two widths no Bitget line has

Add `bitgetBaseInterval(interval, futures)` to `uta.ts`, directly beside
`realityBaseInterval`, which it mirrors:

- `8h` → `4h` (every line)
- `2h` → `1h` (spot only; both futures lines have a native `2H`)
- everything else → itself

In `futures_getCandles` and `spot_getCandles`, when the base differs from the
requested interval, recurse at the base and return
`aggregateCandles(base.data, timeIntervalMap[interval])`, exactly as the
Reality branch already does. In `futures_getCandles` the branch sits **above**
the `coinm_getCandles` delegation so one branch covers all three lines.

This also fixes spec 017 §1.6 without touching the page arithmetic: the
recursive call prices its own pages at the width the venue is really serving,
because that width is now the interval it was called with.

`coinmGranularity`'s `8h`→`6Hutc` arm becomes unreachable and is removed, so
the function cannot silently answer for a width it does not have.

## 2. Contract decisions the spec left open

- **Which base for `8h` — `4h`, `2h` or `1h`?** `4h`: it divides 8h exactly,
  it is native on all three lines, and it is the coarsest such width, so it
  costs the fewest requests (two base bars per output bar). It is also what
  `realityBaseInterval` already picks for 8h.
- **Aggregate `3m` from `1m`, or send `3min`/`3m`?** Send it. The venue has it
  on every line; aggregating would cost 3× the requests to produce a bar the
  venue can serve directly.
- **Leading partial bucket.** `aggregateCandles` already drops it (`uta.ts:266`)
  — a bar missing its own open is wrong data, not late data. Unchanged.

## 3. Blast Radius

1. **Other call sites.** `convertInterval` is called from exactly two places,
   both candle readers (`index.ts:1669`, `:3138`); `coinmGranularity` from one
   (`:1767`). Nothing else in the repo reads either. `aggregateCandles` and
   `realityBaseInterval` gain a sibling; neither is modified, so the Reality
   path and its tests are untouched.
2. **`core/` submodule** — yes, this is `exchange-connector-sh`: shared, public,
   and deployed platform-wide. The change is confined to the Bitget adapter;
   no exported type, endpoint or `BaseReturn` shape moves, so nothing outside
   the Bitget files can see it at compile time.
3. **Contracts this repo owns.** `/candles` keeps its `BaseReturn<CandleResponse[]>`
   shape exactly. What changes is the *content* — Bitget bars at `3m`/`2h`/`8h`
   now have the width they claim. Consumers (main-app indicators and
   server-side backtest, market-archive backfill, both dashboards' client-side
   backtest) read `time`/OHLCV positionally and are unaffected structurally.
   A Bitget `8h` series archived before this change is 6h data stored under an
   8h label; it is overwritten by width-correct data as the archive refills.
4. **Tests that must stay green.** `uta.spec.ts` (Reality base/granularity and
   `aggregateCandles`), plus the whole `npm test` suite in `core/`, and `tsc`
   in **both** `core/` and the parent — the parent's `src/` is a coupled copy
   and type-checks separately.

## 4. Legacy tier (Part 4 of gainium-dev-flow)

**Tier 1.** `bitgetBaseInterval` is pulled out as its own named, tested,
side-effect-free function in `uta.ts` beside the one it mirrors. It is not
taken further: the readers around it stay the infra-coupled methods they are,
and extracting a candle port for Bitget alone would be a rewrite sprung on a
bug fix, not the smallest change that removes the smell on this path.
