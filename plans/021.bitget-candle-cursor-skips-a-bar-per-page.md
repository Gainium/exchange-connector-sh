# 021 — plan

Spec: [`../specs/021.bitget-candle-cursor-skips-a-bar-per-page.md`](../specs/021.bitget-candle-cursor-skips-a-bar-per-page.md)

## Solution

All of it in `src/exchange/exchanges/bitget/index.ts`.

1. **`futures_getCandles` — `from = +to`** (was `+to + timeIntervalMap[interval]`).
   The page just read served opens up to `to - width` (spec §2.1), so `to` is
   the next page's first bar. This cannot double-count: the window is half-open,
   so page N ends one bar before page N+1 begins — which matters here because
   futures returns `allCandles` as accumulated, with no dedup. The break stays
   `from >= windowEnd`, which now fires on the same page it always did (`from`
   used to reach `windowEnd + width` there, now exactly `windowEnd`).

2. **`spot_getCandles` — one `advanceCursor(pageEnd)` helper, three call sites.**
   Spot's two endpoints are opposite at `endTime` (spec §2.1): a historic page
   served opens up to `pageEnd - step`, a recent page up to `pageEnd`. Stepping
   the cursor back one bar — `cursor = pageEnd - step` — is the single rule that
   is contiguous across all four transitions:

   | previous page | covered through | next recent `(cursor, …]` starts | next historic covers from |
   |---|---|---|---|
   | historic | `pageEnd - step` | `pageEnd` ✓ | `pageEnd - step` ✓ |
   | recent | `pageEnd` | `pageEnd` (1 overlap) ✓ | `pageEnd - step` (2 overlap) ✓ |

   At most two bars of overlap, which the method's existing
   `seen`/`deduped` pass at the end already absorbs — that dedup is why the
   uniform back-step is preferable to a per-endpoint rule that would have to be
   threaded through the `coversStart` retry as well.

3. **The termination guard spot now needs.** `chunkEnd` is `Math.min(cursor +
   size * step, to)`, so a cursor that no longer jumps past `to` would re-ask
   the final window until the `totalChunks + 5` safety cap. `advanceCursor`
   returns `false` once a page has reached `to` and every call site breaks on
   it, ending the loop on exactly the page the old arithmetic ended on — no
   extra request, and no change to which bar the last page carries.

Not done, deliberately:

- **The futures overhang stays** — the final page's `to` is still
  `from + pageSpan`, unclamped, so the in-progress candle survives (spec 019
  §1.6). Out of scope by instruction and asserted by a test here.
- **The `8h`/`2h`/`1w` merge (#913) and the span cap (#914) are untouched.**
  Both are asserted still-holding by tests here as well as by their own specs'.
- **Spot's bar at exactly `from`** is served by the historic endpoint reaching
  back past it, so it is present; the recent endpoint's left-exclusive window
  is only a boundary concern, which §2 fixes. Not widened further.

## JIT legacy tier

Tier 0 for futures — one expression. Tier 1 for spot: the cursor rule was
written out three times with no name and the three copies had to agree, so it
becomes one named, commented closure with the venue semantics stated once.
No seam worth cutting beyond that; the runbook's radius rule does not reach the
rest of a 120-line method whose only defect is this arithmetic.

## Blast radius

1. **Other call sites.** `futures_getCandles` is called by `getCandles`, by
   itself for the `8h`→`4h` merge (#913), and via the controller.
   `spot_getCandles` likewise, plus its own `2h`→`1h` / `3m`→`1m` / `1w`→`1d`
   merges. `coinm_getCandles` (v3 inverse) has its own 1000-row pager, a
   different cursor, and is untouched — whether it has the same defect is not
   established here.
2. **`core/` submodule.** Yes — `exchange-connector-sh`, shared and deployed
   platform-wide (Danger List #11). The parent repo only subclasses this file,
   so nothing there changes; `tsc --noEmit` run in both.
3. **Owned/emitted contracts.** None. `BaseReturn<T>` is unchanged, as are the
   HTTP surface, the Redis channels and the paper-trading mirror. What changes
   is only which windows are asked of Bitget, and therefore that the series
   has no holes in it. Downstream consumers (market-archive backfill,
   client- and server-side backtests, indicator warm-up) get a strictly more
   complete series of the same shape.
4. **Other tests on this path.** `candle-span-cap.spec.ts` (#914, spec 019) and
   `candle-intervals.spec.ts` (#913, spec 017) both exercise this loop,
   including multi-page reads; both must stay green. Full suite baseline: 788
   passing.
