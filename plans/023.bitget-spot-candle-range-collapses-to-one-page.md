# Plan 023 — coerce `from`/`to` once in `spot_getCandles`

Spec: [023](../specs/023.bitget-spot-candle-range-collapses-to-one-page.md).
Bug #921.

## Build order

1. `src/exchange/exchanges/bitget/candle-string-range.spec.ts` — the red test.
   Drives `spot_getCandles` against the same stub venue
   `candle-page-boundary.spec.ts` uses (both endpoints, opposite `endTime`
   conventions, a drifting recent floor), once with numeric `from`/`to` and once
   with the strings the HTTP layer delivers, and asserts the two series are
   identical and complete. A second assertion counts venue calls, because "one
   call" is the signature of the defect and a coverage assertion alone would
   pass on a fix that simply asked for a wider first page.

2. `src/exchange/exchanges/bitget/index.ts` — coerce at the top of
   `spot_getCandles`, before any branch reads them:

   ```ts
   from = from == null ? from : +from
   to = to == null ? to : +to
   ```

   Conditional rather than unconditional because both are optional: `+undefined`
   is `NaN`, and the two single-call branches above the pager (`to && !from`,
   `!from || !to`) select on truthiness. `null`/`undefined` must stay what they
   were.

## Contract decisions the spec left open

- **Coerce at the top, not at each use.** Futures coerces at each use; spot has
  three concatenation sites (spec §2.2) plus a recursive self-call for the
  merged `2h`, and one coercion at the entry covers all of them including the
  recursion. It is also the shape that cannot rot: a future arithmetic use of
  `from`/`to` added below it is correct by construction.
- **Not in `getCandles`, not in the controller.** Coercing in the shared
  `getCandles` dispatcher or with a `ParseIntPipe` would change the futures and
  every other exchange's input path. Both are wider than this defect, and
  futures is explicitly out of scope (spec §1.5). If the other exchanges' spot
  pagers have the same latent concatenation they are their own defect, measured
  and filed on their own evidence.
- **`NaN` on a non-numeric query value** (`?from=abc`) is an improvement, not a
  regression: `NaN` is falsy and takes the "no range" branch, where the old
  truthy `'abc'` entered the pager and produced a garbage window.

## Blast radius

`core/` is the shared submodule (`exchange-connector-sh`), so this file is
deployed to the cloud connector fleet and to every self-hosted install. The
change is confined to one method of one exchange adapter:

- **Bitget spot candle reads only.** `futures_getCandles`, `coinm_getCandles`
  and every other exchange are untouched; no shared type, no `BaseReturn`
  shape, no endpoint signature, no Redis channel changes.
- **Consumers** of the repaired path: main-app's non-archive candle fallback
  (charts, server-side backtest, client-side backtest through `/candles`) and
  market-archive's backfill. They receive *more* bars for the same request —
  the bars they asked for — over more venue calls. Rate limits are already
  accounted for: `checkLimits` gates each call, and the numeric path this
  restores is the one `1h`/`4h` already take today through the archive backfill.
- **Live bot trading is not on this path.** Bot indicators read candles through
  the indicator candle provider (archive first), and no order-placement code
  calls `spot_getCandles`.
