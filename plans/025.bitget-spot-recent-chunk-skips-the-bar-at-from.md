# Plan 025 — seed the spot pager one bar early when the first chunk is recent

Implements spec 025 (bug #924).

## Solution

`core/src/exchange/exchanges/bitget/index.ts`, `spot_getCandles`, the
`let cursor = from` seed (:3350). Back-step the seed by one bar **iff the first
chunk will be served by the recent endpoint**, using the same predicate the loop
itself applies (`Date.now() - cursor <= lookbackMs`) evaluated on the
back-stepped value, so the seed cannot disagree with the branch the loop then
takes:

```ts
let cursor = from
if (Date.now() - (cursor - step) <= lookbackMs) {
  cursor -= step
}
```

Nothing else changes. `chunkEnd = Math.min(cursor + size * step, to)` follows
the seed, so the first recent page is still exactly `recentMaxSize` bars wide.

### Why the seed and not `startTime: cursor - step` at the call site

Spec 025 §3 gives the design reason (a second back-step at every later
boundary). There is a harder one, measured live 2026-09-23: the venue anchors
its `limit` cap on `endTime` and truncates at the START. Asking
`startTime: cursor - step` while `chunkEnd` stays at `cursor + 1000 * step`
makes a 1001-bar window at `limit: 1000`, and the venue returns bars
`from + step … chunkEnd` — byte-identical to today's defective output. That
variant is a **no-op in production**. Moving the seed moves `chunkEnd` with it,
keeping the window at exactly 1000 bars.

The spec's stub is written to that measured shape (`rows.slice(-limit)`), so
the call-site variant fails the test rather than passing it.

### Why it is conditional

The historic endpoint is `endTime`-anchored and already reaches back to exactly
`cursor` (spec 025 §2.2), so a history-starting range loses nothing today. An
unconditional seed would hand it a bar opening before `from` and shift every
subsequent chunk boundary — spec 025 §1.3 forbids both.

Known 1-bar sliver: if `from` is inside the lookback but `from - step` is not,
no back-step happens and the bar at `from` is still lost. The lookback constants
are deliberately set a full day inside the measured cliff
(`getSpotIntervalLookbackMs`), so this is one bar of a 30/59/239-day window, and
it degrades to today's behaviour rather than to something new. Taking the other
branch instead would emit an out-of-window bar, which §1.3 rules out.

## JIT extraction tier

**Tier 0.** The causal path is two adjacent statements inside a method that has
been repaired four times in the last week (#918, #920, #921, #923) and is under
active, well-specified test. The decision being fixed is "which window does the
first call ask for", which is inseparable from the pager's own loop state —
extracting it would create a seam with one caller and no second implementation,
and would churn a hot file mid-bug-series. Not Tier 1: nothing new becomes
independently testable that the stub harness does not already reach.

## Blast radius

1. **Other call sites.** `spot_getCandles` is called from `getCandles`
   (:3140, the spot branch) and recursively by itself for a merged width
   (:3229). No other caller in either repo; `futures_getCandles`,
   `coinm_getCandles` and every non-Bitget adapter have their own pagers and
   are not touched. The changed lines are inside the `from && to` paging branch
   only — the `to`-only and no-range branches return before it.
2. **`core/` submodule.** Yes — this is `exchange-connector-sh`, shared and
   deployed platform-wide. The parent `exchange-connector` pointer needs
   bumping at ship time. No exported type, signature or endpoint shape changes,
   so paper-trading (the contract mirror) needs nothing.
3. **Owned contracts.** `BaseReturn<T>` unchanged. `GET /candles` unchanged in
   shape — the same `CandleResponse[]`, one bar longer at the leading edge for
   affected ranges. No Redis channel, no rate-limit key, no admin-config touch.
   Downstream consequence to state on the card: main-app's server-side backtest
   and both dashboards' client-side backtests over an affected Bitget spot range
   will now include the opening bar, so a result can shift slightly. That is the
   correction, not a side effect.
4. **Tests that must stay green.** `candle-page-boundary.spec.ts` (#918 — the
   later-boundary tiling this must not disturb), `candle-overhang-dedup.spec.ts`
   (#920), `candle-string-range.spec.ts` (#921), `candle-span-cap.spec.ts`
   (#914/#919), `candle-intervals.spec.ts` (#913), plus the whole suite.
