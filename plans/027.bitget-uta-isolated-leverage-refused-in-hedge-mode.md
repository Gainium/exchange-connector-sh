# 027 — plan

## Solution

1. `uta_setIsolatedLeverage(symbol, N)` (private): reads the hold mode
   (`uta_getHedge` → `/api/v3/account/settings`), then sends the §2.1 hedge
   request or the §2.2 per-side requests through `utaRequest` (limiter,
   profiler, retry policy). Returns `notok` on the first refusal.
2. `uta_changeLeverage`: cross as before; isolated via (1), refusal logged.
3. `uta_changeMarginType(symbol, margin, leverage)`: for ISOLATED, (1) and
   return its failure. `futures_changeMarginType` now passes `leverage` (it
   already received it; the classic path already used it).
4. `setLeverageV3` params: `leverage` optional, `longLeverage` /
   `shortLeverage` added.

JIT tier 0 — the touched methods are already narrow adapter methods.

## Blast Radius

- Call sites: `futures_changeLeverage` / `futures_changeMarginType` only;
  classic (v2) paths untouched.
- File is under `core/` (exchange-connector-sh): shared by every connector
  deployment, cloud and self-hosted. No `BaseReturn` shape change, no endpoint
  change.
- Behaviour change for callers: on a unified account, an isolated bot's
  margin step can now return `notok` (main-app `loadData` reports
  `Cannot set margin for …` as a bot error) where it previously returned
  success while the venue held a different leverage. One extra
  `/api/v3/account/settings` read per leverage/margin call.
- Other tests on this path: `uta.spec.ts` (all green).
