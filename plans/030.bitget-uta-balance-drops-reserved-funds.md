# 030 — plan

Spec: [030](../specs/030.bitget-uta-balance-drops-reserved-funds.md).

## Build order

1. exchange-connector-sh `src/exchange/exchanges/bitget/uta.ts`
   `convertUtaAssets`: total = `equity` when positive, else today's
   `balance` / `available + locked`. `UtaAsset` gains the optional
   `equity` field the venue already sends.
2. websocket-connector-sh `src/userStream.ts`
   `prepareBitgetUtaOutboundAccountInfo`: the same anchor; `BitgetUtaAccount`
   coin entries gain the optional `equity` field.
3. Bump both parents' `core/` pointers.

The two conversions cannot share code (separate repos); they are kept
line-for-line alike so §4.4 holds by inspection and by the paired tests.

## JIT extraction tier

Tier 0. `convertUtaAssets` is already a pure, tested function; the stream
conversion is a private method on the connector with no I/O and already
driven directly by tests. Nothing to extract.

## Blast Radius

1. Call sites: `convertUtaAssets` is called only from `uta_getBalance`;
   `prepareBitgetUtaOutboundAccountInfo` only from the v3 `account` push
   handler. Both are UTA-only; classic accounts never reach them.
2. Both files are in `core/` submodules — shared by cloud and self-hosted.
   The `FreeAsset` / `outboundAccountPosition` shapes are unchanged; only
   the numbers inside them change, for unified accounts only.
3. Contracts: `/balance` response and the `outboundAccountPosition` event
   keep their shape. Consumers sum `free + locked`; that sum now includes
   unrealised PnL in the coin, as the classic COIN-M path already does.
   On a unified USDT-M leg the total now includes unrealised PnL where the
   classic USDT-M path reports wallet balance; the venue gives no per-coin
   PnL to subtract, and equity is the figure the venue shows.
4. Other tests on the path: `uta.spec.ts` (conversions, pooled
   collateral), `bitgetUtaStream.test.ts` (account push). Their fixtures
   carry no `equity` and must stay green through §4.2.
