# 036 — plan: report the Bybit linear minimum order value

> **Withdrawn (1.27.14).** The premise was wrong: Bybit does not enforce `minNotionalValue` on these API orders — it fills linear orders far below it. Reporting it made consumers raise or refuse orders the venue would have filled, so the mapping was reverted to 0. Do not re-introduce it without checking filled opening orders, not only refusals.

Spec: [036](../specs/036.bybit-linear-min-order-value-reported-as-zero.md).

## Solution

Root cause per spec §3: the linear branch of `getAllExchangeInfo` hard-codes
`quoteAsset.minAmount: 0`. It becomes
`parseFloat(lotSizeFilter.minNotionalValue)`, falling back to `0` when the
field is absent or not a finite number (§1.3). The inverse branch keeps `1`
(contract size, §1.3). The commented-out expression and its `@ts-ignore`
go; the SDK's instrument type does not declare `minNotionalValue`, so it is
read through a narrow cast, the same way `symbolType` is read a few lines
above.

JIT tier 0: a one-expression change inside an existing mapping; nothing on
the path mixes a decision with I/O that this change has to cut.

## Build order

1. Consumers first (spec §4): the downstream close/reduce paths that check
   a remainder's value against the quote minimum must exempt reduce-only
   futures orders. That change is outside this repo.
2. `exchange-connector-sh` (this repo): mapping + spec, release.
3. `exchange-connector` parent: bump the `core/` pointer, release.
4. Consumers refresh stored exchange info on their own schedule; no data
   migration.

Step 2 may be merged before step 1 only if it is not deployed before it.

## Blast Radius

1. Call sites: `getAllExchangeInfo` is the only mapper of linear/inverse
   instruments; `getExchangeInfo` / `futures_getExchangeInfo` /
   `futures_getAllExchangeInfo` delegate to it. The EU-host merge below it
   runs for spot only.
2. Under `core/` — shared by every connector deployment (cloud and
   self-hosted). Behaviour changes only for Bybit linear instruments.
3. Contract: `BaseReturn<ExchangeInfo[]>` shape unchanged; one value goes
   from 0 to the venue minimum. Every reader of the stored pair minimum
   sees it: order sizing and refusal of sub-minimum opening orders (the
   intended effect — those orders are rejected by the venue today), pair
   pickers, backtest/preset sizing, and the close/reduce paths named in
   spec §4 (the reason for build-order step 1).
4. Tests: the new `bybit/linear-min-order-value.spec.ts`, the other Bybit
   spec, and the full suite.
