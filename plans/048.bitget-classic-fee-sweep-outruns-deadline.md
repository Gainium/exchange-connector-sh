# 048 — plan: Bitget classic fee sweep via `all-trade-rate`

## Build order

1. `src/bitget-custom/rest-client-v2.ts`: add `getAllTradeRate({ businessType })`
   → `GET /api/v2/common/all-trade-rate` (signed, same client as the v3 fee
   calls; the `bitget-api` SDK has no method for it).
2. `src/exchange/exchanges/bitget/index.ts`: private
   `classic_getAllUserFeesBatch(businessType, listing, getOne, timeProfile)`;
   `spot_getAllUserFees` (`spot`) and `futures_getAllUserFees` (`mix`) call it
   first and keep their existing per-pair fan-out as the fallback when it
   returns `null`.

## Decisions the spec left open

- Probe pair = first listed pair present in the batch; exact equality of the
  parsed numbers (both endpoints return the same string form).
- Probe failure → the call's result is that failure (main-app keeps the stored
  rates; a refusal reaches `byAccountMode` / the auth-failure counter as before).
  Running the fan-out after a failed probe would only spend the deadline again.
- Raising concurrency was rejected: at the documented 10 req/s/UID the spot
  listing (~3,660 pairs) needs ≥ 366 s, more than the 300 s deadline.

## JIT tier

Tier 0 on the existing fan-out (untouched); the new code is one method on the
adapter, the same shape as `uta_getAllUserFees`.

## Blast Radius

1. Callers: `getAllUserFees` → `byAccountMode` only. `uta_getAllUserFees` untouched.
2. File is under `core/` (exchange-connector-sh): ships to every connector
   instance; pointer bump through `psh`.
3. Contracts: `/fees/all` keeps `BaseReturn<(UserFee & {pair})[]>`; the only
   new field value is the existing optional `source: 'ladder'` (already in
   `UserFee`, already persisted and honoured by main-app's fee sweep).
4. Other tests on this path: `uta.spec.ts` classic fan-out / refusal cases —
   their stubs have no `getAllTradeRate`, so they exercise the fallback and
   stay green.
