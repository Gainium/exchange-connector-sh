# Plan 051 — cap Bitget linear futures `free` at the venue's spendable figure

## 1. Solution

In `futures_getBalance` (linear product types only), after spec 006's
`walletBalance` and `committed`:

```
free   = isFinite(crossedMaxAvailable)
           ? clamp(min(walletBalance - committed, crossedMaxAvailable), 0)
           : walletBalance - committed
locked = walletBalance - free
```

Tier 0 (Part 4): the change is three lines inside the existing per-row
mapping.

### Not chosen

- *Subtract `max(0, -unrealizedPL)`.* That re-derives the venue's figure from
  our own arithmetic. It also misses isolated PnL, maintenance margin and
  fees. The venue publishes the figure it enforces, so we use it.
- *`max(crossedMaxAvailable, isolatedMaxAvailable)`.* Cross is the looser
  mode, so the max is the cross figure whenever there is a loss. It adds a
  second field for no case we have evidence of.

## 2. Blast Radius

1. **Call sites.** `futures_getBalance` is reached from `getBalance()` (classic
   accounts) and the `/balance` endpoint. The UTA path (`uta_getBalance`) is
   untouched.
2. **`core/`.** Yes, this is `exchange-connector-sh`. The parent does not
   override this method; `tsc` passes in both trees.
3. **Contracts.** The `BaseReturn<FreeAsset>` shape is unchanged. Only the
   split between `free` and `locked` moves, and only for linear accounts whose
   venue figure is below `walletBalance - committed`. The total is unchanged.
   Consumers: the main-app `balances` rows (the bot funds check reads `free`,
   which drops to what the venue accepts) and the Portfolio widget ("In limit"
   grows, the total is unchanged).
4. **Second writer.** The websocket-connector classic Bitget futures `account`
   stream writes the same rows. It gets the same cap from the push's
   `maxOpenPosAvailable` (websocket-connector-sh spec 023). Without it, every
   push would undo this fix between REST polls.
5. **Tests.** `bitget/futures-balance.spec.ts`. Its spec-006 crossed and
   isolated fixtures carry a venue figure below wallet minus margin, so
   their `free`/`locked` assertions move to this spec's values. The total
   assertions are unchanged.
