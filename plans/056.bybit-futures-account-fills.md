# Plan 056 — Bybit futures account fills

## Build order
1. `src/exchange/exchanges/bybit/accountFills.ts`: a pure row mapper, the kept exec types and the
   forced-close typing (Tier 2, new file, mirrors `bitget/accountFills.ts`).
2. `src/exchange/exchanges/bybit/index.ts#getAccountFills`: linear/inverse only, spot → `[]`.
3. `src/exchange/types.ts`: a doc-only note on `fillType`.
4. main-app `specs/277.invariants.json`: add `bybitLinear`/`bybitInverse` to
   `deals.closed-outside-profit-unknown-on-fills-venue` (still `observe`).

## Decisions the spec left open
- Normalise forced-close names in the connector, not in main-app. The consumer predicate already knows
  `liquidation`/`unwindCounterparty`, so no paired main-app code ship is needed and Bitget/Kraken
  behaviour is untouched.
- Request unfiltered and filter client-side. Bybit's `execType` filter takes one type per call, so a merged
  read of three types would not page consistently.

## Blast radius
- Callers of `getAccountFills` (main-app):
  - `venueCloseEvidenceFor`: outside-close settlement and stream-liquidation pricing. Bybit deals are now
    priced from fills where they used to be "profit unknown"; when evidence exists, a liquidation reported
    on the stream is priced from the venue's fills instead of the stream price.
  - `readLiquidationFills` / `bookPartialLiquidation`: gated by `partialLiquidationBookable`
    (krakenUsdm).
  - `settleWriteOffFromVenueFills`: gated on krakenUsdm.
  - `positionReconciler/orderProbe`: read-only diagnostics.
  - The Kraken repair script.
  None of these changes *when* a deal is judged closed outside the bot.
- `core/` = exchange-connector-sh: shared, and the parent's pointer is bumped at push (`psh`).
  paper-trading has no `/accountFills` override and is unaffected.
- Rate limit: one `checkLimits('getAccountFills')` per venue page, at most 5 per read.
- Other tests: the full core mocha suite (1277) stays green; core and parent `tsc` are clean.
