# 032 — maker rebates booked as fees

Follows the observed-fee capture (1.20.8), which introduced
`helpers/orderFee.ts`.

## 1. Definition

### 1.1 — expected

`feePaid` is the cost of the order: what the venue charged, net of any rebate
it paid on the same order, in one currency. A line that is a rebate lowers the
cost. A currency whose lines net to a rebate (or to zero) is not a fee and is
omitted, so the caller keeps its estimate (rule 2 of the module header).

### 1.2 — actual

`chargeMagnitude` takes `Math.abs` of every line before summing. A rebate is
added to the cost instead of subtracted from it. A net rebate is reported as a
positive fee.

## 2. Evidence

- Hyperliquid's public `userFills` (read live, 11 active BTC traders, ~17k
  fills): every taker fill (`crossed: true`) has `fee > 0`; every maker fill on
  a rebate tier has `fee < 0` (e.g. `"fee":"-0.017784","feeToken":"USDC"`).
  Hyperliquid's convention is **positive = charge**. The module header said the
  opposite.
- OKX `fee` and Bitget `fee` / `feeDetail.totalFee` / UTA `feeDetail[].fee` are
  "effect on the balance": **negative = charge**, positive = rebate.
- Binance `commission`, Bybit `cumExecFee` / `cumFeeDetail`, KuCoin `fee`,
  Coinbase `total_fees`: **positive = charge**.
- Current helper output: HL `[+0.10, -0.04]` → `0.14` (want `0.06`); HL
  `[-0.017784]` → `0.017784` (want nothing); OKX `fee: "0.02"` → `0.02` (want
  nothing).
- Hyperliquid's `getOrder` reaches this helper on every filled order it
  re-prices from fills (the "Calculated price … based on fills" log line).

## 3. Assumption (root cause)

The helper has no notion of sign convention, so it cannot tell a charge from a
rebate. The fix is a per-venue convention argument, signed netting per
currency, and dropping currencies that net to ≤ 0.

## 4. Behaviour

- §4.1 Each caller states its convention: `'charge-positive'` or
  `'charge-negative'`. There is no default.
- §4.2 Lines are converted to signed cost and summed per currency.
- §4.3 A currency whose net is ≤ 0 is omitted. If none remain, `{}`.
- §4.4 Rule 1 (zero / missing / NaN → omitted) and the multi-currency
  `feeBreakdown` shape are unchanged.
- §4.5 `normalizeSidedOrderFee` follows the same rule for its single line.

## 5. Out of scope

- A net rebate is not booked as a negative cost. Consumers treat a missing
  fee as "use the estimate", so a rebate-tier order still books the estimate.
  That is the documented contract, not this defect.
- The websocket stream path is separate code (websocket-connector-sh).
