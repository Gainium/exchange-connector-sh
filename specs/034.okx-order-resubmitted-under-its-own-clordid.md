# 034 — OKX order re-submitted under its own clOrdId

Bug spec (Definition / Evidence / Assumption).

## §1 Definition

`OKXExchange.openOrder` sends one order and then reads it back by `clOrdId`.
Both steps share one `.catch`, which hands any retryable failure to
`handleOkxErrors(this.openOrder, …)`, and that **re-submits the order with the
same `clOrdId`**. If the order already reached OKX, either because the submit
succeeded and only the read-back failed, or because the submit's response was
lost (`50001`/`50004`/`50013`/`50026`/transport errors, all in `retryErrors`),
OKX refuses the second submit with `51016` ("clOrdId already exists"). The
connector returns that refusal as `NOTOK`. The caller then writes off an order
that is live on the venue.

§1.1 Expected: an order OKX accepted is returned as placed. It is never
reported as refused.
§1.2 Expected: a submit is never repeated after OKX has accepted it.
§1.3 Unchanged: the request sent to OKX (price, size, side, ids), and the
number of orders a caller places.

## §2 Evidence

Production logs, OKX spot DCA bots. Each order's OKX creation time (from the
user stream) is followed 0.75–0.9s later by the bot receiving "already exists"
**for the same clOrdId**. This holds for the original base/safety order, for
its regenerated `…2` replacement, and for a take-profit, three times in five
seconds. The `…2` id is generated once and sent once by the bot, so a second
submit under it can only come from inside the connector. All three orders
stayed live on OKX while the bot recorded them CANCELED.

## §3 Assumption

The connector does not log which OKX error triggered the retry (no
`OKX Too many requests`, `socket hang up`, `ECONNRESET`, `EAI_AGAIN` or TLS
line in that window), so the trigger is one of the *silent* retry classes. The
fix does not depend on which one: it removes the re-submit after a successful
submit, asks OKX before any re-submit after a failed one, and treats `51016`
as "look it up".

## §4 Behaviour after the fix

§4.1 Submit OK, read-back fails → fall back to `getOrder` (read-only retry).
Never `openOrder`.
§4.2 Submit fails with a retryable error → before re-submitting, look up the
`clOrdId`. If OKX has it, return it.
§4.3 Submit fails with `51016` → look up the `clOrdId`. If OKX has it, return
it as placed. If not, return the original refusal unchanged.
§4.4 Any other refusal (e.g. insufficient balance) → unchanged.
