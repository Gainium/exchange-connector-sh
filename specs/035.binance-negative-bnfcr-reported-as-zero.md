# 035 — Binance USDⓈ-M balance read reports a negative BNFCR as 0

Pairs with main-app-sh spec 158 (BNFCR priced at 1 USD in the portfolio
snapshot). That change values a negative BNFCR row; this one is what lets the
row stay negative.

## 1. Definition

### 1.1 — expected

On a Binance USDⓈ-M account in Multi-Assets (Credits) mode, settled PnL,
fees and funding are booked to BNFCR, whose wallet balance goes negative
after losses. The futures balance read (`futures_getBalance`) reports that
debt: the BNFCR row's `free + locked` equals its `walletBalance` when that is
negative, which is the figure the user stream already publishes
(`crossWalletBalance`).

### 1.2 — actual

`free` is `maxWithdrawAmount` and `locked` is `walletBalance −
maxWithdrawAmount` only when `walletBalance > 0`, else 0. A negative BNFCR
has `maxWithdrawAmount` 0, so the row reads `free 0, locked 0` and the debt
disappears from every reader of the stored balance.

### 1.3 — unchanged

- Every other asset, and a BNFCR row with a zero or positive wallet balance,
  maps exactly as before.
- `locked` is never negative.

## 2. Evidence

- Prod, read-only (2026-10-13/14): the reporter's two Multi-Assets accounts
  held BNFCR −4,250.82 / −3,562.88 (written by the user stream). Each
  balance refresh over REST — the on-demand refresh at 21:55Z and the
  00:45Z snapshot cron, which refreshes before valuing — rewrote the row as
  `free 0, locked 0`; the 01:48Z snapshot carries no BNFCR and its
  account total equals USDC + BNB. The row is still 0 afterwards.
- Binance `GET /fapi/v2/account` lists a negative BNFCR as
  `walletBalance < 0, maxWithdrawAmount 0` (fixture in
  `pooledMargin.spec.ts`).

## 3. Assumption (hypothesis)

The REST mapping is the only thing turning the debt into 0: the stream
writes the negative value, and main-app stores the REST `free` verbatim.
A test feeding a negative BNFCR asset through `futures_getBalance` fails
today with `free 0`.

## 4. Open questions

- Other assets with a negative wallet balance (a USDT row in a non-Credits
  Multi-Assets account) are left as they are: valuing them is outside this
  change's scope and unverified on prod.
