# 036 — Bybit linear contracts report no minimum order value

> **Withdrawn (1.27.14).** The premise was wrong: Bybit does not enforce `minNotionalValue` on these API orders — it fills linear orders far below it. Reporting it made consumers raise or refuse orders the venue would have filled, so the mapping was reverted to 0. Do not re-introduce it without checking filled opening orders, not only refusals.

## 1. Definition

### 1.1 — expected

For a Bybit linear contract (USDT/USDC perpetuals and dated futures), the
exchange-info read (`getAllExchangeInfo`, and `getExchangeInfo` which
filters it) reports the venue's minimum order value in
`quoteAsset.minAmount`: the instrument's `lotSizeFilter.minNotionalValue`
(5 USDT on most USDT perpetuals, set per instrument by the venue). This
matches what the connector already reports for Binance USDⓈ-M (`NOTIONAL`
filter) and Bitget USDT-M (`minTradeUSDT`).

### 1.2 — actual

`quoteAsset.minAmount` is a hard-coded `0` for every linear instrument; the
`minNotionalValue` mapping is commented out. Every reader of the pair's
quote minimum sees no minimum, so an opening order below the venue minimum
is only discovered when the venue rejects it (`110094`, "Order notional
value below the lower limit").

### 1.3 — unchanged

- **Inverse** instruments keep `quoteAsset.minAmount = 1`. On coin-margined
  contracts consumers read this field as the **contract size** (Binance
  COIN-M reports `contractSize` there), and a Bybit inverse contract is 1
  USD. Mapping the venue's inverse minimum notional (up to 100 USD) into it
  would rescale every inverse order.
- A linear instrument with no `minNotionalValue` (or an unparsable one)
  reports `0`, as today — never `NaN`, never an invented default.
- Spot mapping, base-asset fields, leverage and precision are untouched.

## 2. Evidence

- `bybit/index.ts` linear/inverse branch:
  `minAmount: !inverse ? 0 : 1 /* +\`${d.lotSizeFilter.minNotionalValue || 1}\` */`.
- History: the field was mapped to `minNotionalValue` when Bybit introduced
  the minimum (April 2024), then zeroed for linear in November 2024. That
  change is consistent with the consumer behaviour in §4: closing orders are
  exempt from the venue minimum, and a single quote minimum applied to
  closes would stop sub-minimum remainders from being closed.
- Bybit V5 `GET /v5/market/instruments-info` (linear) returns
  `lotSizeFilter.minNotionalValue` (docs example BTCUSDT: `"5"`). Bybit's
  derivatives rules: the limit does not affect closing-position orders.

## 3. Assumption (hypothesis)

The hard-coded `0` is the only thing hiding the venue minimum: a test that
feeds a linear instrument row with `minNotionalValue: "5"` through
`getAllExchangeInfo` fails today with `quoteAsset.minAmount` `0`.

## 4. Open questions

- **Consumers apply the quote minimum to closing orders.** Some downstream
  close/reduce paths (remainder sweeps after a take-profit, reduce-only
  remainder closes, reducing deal funds) test the remainder's value against
  `quoteAsset.minAmount` without exempting reduce-only futures orders. With
  `0` those paths always proceed; with `5` a remainder worth under 5 would
  be left open although the venue would accept the close. The same gap
  already exists today for every venue that reports a futures minimum
  notional. Shipping this mapping should wait until those consumers exempt
  reduce-only futures orders from the quote minimum.
- Bybit also enforces a minimum notional on inverse contracts now; reporting
  it needs a separate field, not this one (see §1.3).
