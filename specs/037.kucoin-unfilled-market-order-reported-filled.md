# 037 — A KuCoin order that closed with nothing executed is reported FILLED

## 1. Definition

### 1.1 — expected

`KucoinExchange.convertOrder` maps a KuCoin order record to a `CommonOrder`.
An order that is no longer active (`isActive: false`) and executed nothing
(`dealSize` 0) did not fill: its status is `CANCELED`, with `executedQty` 0.

### 1.2 — actual

The status is decided by `cancelExist` alone once the order is inactive:
`!cancelExist` → `FILLED`. KuCoin closes a market order it could not execute
(for example, an account without the funds for it) without setting
`cancelExist`, so the record comes back `FILLED` with `executedQty` 0.

Consumers read `FILLED` as "the order executed". The bot engine, given
`FILLED` with `executedQty` 0 and no fills, books the order's full requested
size (`origQty`) as bought, so the deal records coins and spending that never
happened.

### 1.3 — unchanged

- An active order: `NEW` with nothing executed, `PARTIALLY_FILLED` with some.
- An inactive order with anything executed: `FILLED` unless `cancelExist`,
  then `CANCELED` — and `executedQty` carries `dealSize` either way, so a
  part-filled order still reports what moved.
- Price, fee, fills and every other field.
- Spot and futures share this mapping; both get the rule.

## 2. Evidence

- A market safety order: the private user stream reported it `CANCELED`
  with 0 executed; the connector's placement read (`getOrderById` →
  `convertOrder`) answered `FILLED` with `executedQty` `"0"` for the same
  order, and the bot booked the full `origQty`. The account's quote balance
  was below the order's value; the base balance did not change.
- A later read of the same order through `getOrder` again answered `FILLED`
  with `executedQty` `"0"`.

## 3. Assumption

KuCoin leaves `cancelExist` false on a market order it closes unexecuted,
so `cancelExist` cannot by itself distinguish a fill from a non-fill;
`dealSize` can. Hypothesis, supported by the evidence above.
