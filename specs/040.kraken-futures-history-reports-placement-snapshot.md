# 040 — Kraken Futures order read-back reports the placement snapshot

Bug spec (SKILL.md Part 0). Scope: `src/exchange/exchanges/kraken/index.ts`
(`getOrder` Futures history fallback, fill lookup).

## §1 Definition

### §1.1 Expected

`getOrder` for a Kraken Futures order that is no longer on the live view
reports the order's final executed size and a status that follows from it:
`FILLED` when everything executed, `PARTIALLY_FILLED` only when part of it
really did not, `CANCELED` (with whatever executed) when it ended cancelled.

### §1.2 Actual

The history fallback takes the first `OrderPlaced` event for the client id.
That event is the order as it looked the instant it was accepted. A MARKET order
that executed a small slice on acceptance and the rest a moment later is
reported `PARTIALLY_FILLED` at the slice — on every read, indefinitely. Later
`OrderUpdated` / `OrderCancelled` events for the same order are never looked at.

Downstream the bot keeps a deal in start on a fraction of its base order, and
when that deal is stopped the real position stays on the venue untracked.

## §2 Evidence

- Production bot log: MARKET base orders repeatedly read back as
  `PARTIALLY_FILLED` at 3%, 20% and 0.07% of their size, minutes after
  placement, while the user stream was down. The same orders were read again
  hours later with the identical answer.
- The account's venue position afterwards held the full sizes of those orders.
- Code: the fallback's `find` matched `OrderPlaced | OrderRejected |
  OrderCancelled` and returned the first match; `OrderUpdated` was not handled.

## §3 Assumption (root cause, hypothesis)

The fallback reads a stale event. Choosing the latest event for the client id
(by timestamp; terminal over update over placement at a tie) and, when that
still shows less than the order size, cross-checking the account fills
recorded against the client id, yields the true executed size.

## §4 Requirements

- §4.1 Latest recorded state wins, regardless of element order.
- §4.2 When the latest state shows less than the order size, the account fills
  for this order are summed; a larger sum replaces the snapshot (capped at the
  order size) and prices the order.
- §4.3 No regression: a genuine partial stays partial, a cancel stays
  `CANCELED` with its executed part, the stale-placement not-found rule (an
  old state with nothing executed, after the live view said unknown) still
  applies.
- §4.4 A fully filled order costs no extra fills read for its size.
