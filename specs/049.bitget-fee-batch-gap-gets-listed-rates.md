# 049 — Bitget fee batch leaves the USDC-M pairs on the listed rate

Bug spec. Owner: `src/exchange/exchanges/bitget/index.ts`
(`classic_getAllUserFeesBatch`). Follows spec 048.

## 1. Definition

Expected: a classic Bitget futures key's `getAllUserFees` returns this
account's own maker/taker rate for every listed pair, USDC-M included, as the
per-pair sweep did before spec 048.

Actual: `all-trade-rate?businessType=mix` returns only the USDT-M symbols. The
USDC-M contracts (`BTCPERP`, …) are listed but absent from the batch, so since
spec 048 they get the publicly listed rate, marked `source: 'ladder'`. main-app
never lets a `ladder` rate overwrite a stored one, so existing USDC-M rows stop
refreshing, and a new pair or a new connection is stored with the listed rate
instead of the account's VIP rate.

## 2. Evidence

- Public listing 2026-11-21: `USDT-FUTURES` 892 contracts + `USDC-FUTURES` 50 =
  942 pairs, the futures listing size.
- Prod `Gainium-cron-jobs` log: every `bitgetUsdm` connection logs `Fee Update
  | bitgetUsdm returned published-schedule rates for 50/942 pairs`, from the
  deploy of spec 048 onward and never before it.
- Code: the batch's final `listing.map` gives every pair missing from `rates`
  the listed rate, with no per-pair call.

## 3. Assumption (hypothesis)

Missing pairs are a small, stable gap (the 50 USDC-M contracts) that the
per-symbol `trade-rate` still answers, as it did before spec 048.

### §3.1 After the probe passes, each listed pair the batch leaves out is asked per-symbol (8 at a time, through the same rate limiter) and gets that answer. Pairs the batch carries are not asked again.
### §3.2 A pair whose own call also fails keeps the listed rate, marked `source: 'ladder'`.
### §3.3 A unified-account or key refusal on a gap call is the call's result, as in the sweep.
### §3.4 More than 100 missing pairs (≈10 s at 10 req/s/UID) are not asked; they keep the listed rate marked `ladder` (spec 048 §3.3 behaviour), so a batch that carries little cannot rebuild the fan-out.

Test: `src/exchange/exchanges/bitget/all-trade-rate.spec.ts` (`049 §…` cases).

## 4. Out of scope

- Spot and USDT-M keep the single batch call; only the gap is asked.
- `bitgetCoinm`: `mix` matches no listed coin-margined pair, so it already falls
  back to the full per-pair sweep (unchanged).
