# 054 — Bitget USDT-M publishes its futures account fills

Bug spec (Definition / Evidence / Assumption). Test:
`src/exchange/exchanges/bitget/account-fills.spec.ts`.

## §1 Definition

`GET /accountFills` (`getAccountFills`) is the read-only "executions on the account" feed main-app uses to
learn what closed a futures position the bot did not close (a venue liquidation, a hand close on the
exchange). Kraken Futures answers it; every other venue answers the abstract default, an empty page.

**Expected.** On Bitget USDT-M (classic account) the feed returns the account's own futures fills, newest
first, so a caller can price an outside close from the venue's own record.

**Actual.** Bitget answers an empty page. main-app therefore books a Bitget futures deal whose position
was liquidated with no exit price at all, a profit of about zero instead of the loss.

- §1.1 Each `/api/v2/mix/order/fills` row maps to an `AccountFill`: `price`, `quantity` (`baseVolume`),
  `timestamp` (`cTime`), the raw `tradeSide` as `fillType` (`burst_close_long` = liquidation),
  `enterPointSource` as the new optional `source` (`API`, `WEB`, `IOS`, `ANDROID`, `SYS`), and the fee in
  the quote coin as the new optional `fee` (absent when charged in another coin). The fill record carries
  no client order id, so `clientOrderId` is empty; `source` is what tells a bot's API order from a hand
  trade.
- §1.2 `side` is the direction of the TRADE. Bitget's hedge-mode `side` names the position (`buy` +
  `close` closes a long), so the direction is read off `tradeSide` when it names the position, else from
  `side` (inverted for a hedge-mode `close`).
- §1.3 Both USDT-M product lines (USDT, USDC) are read, at most 100 fills each, merged newest first.
  `sinceMs` pages backwards (`endTime = sinceMs - 1`), as on Kraken.
- §1.4 Spot and Unified Trading Accounts keep answering an empty page (not read).

## §2 Evidence

A Bitget USDT-M futures deal whose position the venue liquidated was closed by main-app with a profit of
a few cents where the price move alone was a loss of several USDT: main-app's fill read got `[]`. The
Bitget adapter has no `getAccountFills` override (`grep`), so it answered the abstract default.

## §3 Assumption

The empty page is the abstract default, not a venue refusal: Bitget publishes fills
(`/api/v2/mix/order/fills`, already wrapped by `bitget-custom/rest-client-v2.ts#getFuturesFills`).

## §4 Contract

Additive only: two OPTIONAL fields on `AccountFill` (`source`, `fee`), no new route, no change to
`BaseReturn` or to Kraken's answer. main-app's mirror type gains the same two optional fields.
